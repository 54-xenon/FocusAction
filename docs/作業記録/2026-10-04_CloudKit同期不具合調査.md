# 2026-10-04 CloudKit 同期不具合の調査

ブランチ: `bugfix/build2`

## 症状

- TestFlight で実機に入れたアプリで、CloudKit のデータ同期が行われない。
- アプリ自体は普通に動き、ローカルへの保存もできている。

## 調査結果

### アプリ側（問題なし）

- `FocusSession` / `Tag` の全プロパティにインラインのデフォルト値がある。
- リレーション（`FocusSession.tag` ⇔ `Tag.sessions`）は両側 Optional で、inverse も設定済み。
- iOS / watchOS の entitlements で、コンテナID `iCloud.FocusActionContainer`・`aps-environment`・`remote-notification` がそろっている。
- 過去に削除した `tags: [String]` と現在の `tag` はフィールド名が別（`CD_tags` / `CD_tag`）なので、型の衝突はない。

### CloudKit Console のログ

```
"operationType":"RecordSave"
"overallStatus":"USER_ERROR"
"error":"BAD_REQUEST"
"returnedRecordTypes":"_pcs_data"   ← 暗号化キー用のシステムレコード。毎回出るもので無関係
```

iPhone からのレコード保存が、サーバーに不正なリクエストとして拒否されていた。

## 原因

**Production 環境の CloudKit スキーマに、アプリが保存しようとするフィールドが存在しない。**

| インストール方法 | CloudKit の環境 |
|---|---|
| Xcode から実行（Development 署名） | Development |
| TestFlight / App Store / Ad Hoc | Production |

- Development では、存在しないフィールドが保存時に自動で作られる。
- Production では自動で作られず、`BAD_REQUEST` で拒否される。
- `c25aa1d` で `Tag.sessions` を追加してスキーマが変わったが、Production に反映していなかった。

## 対処手順

1. **Xcode から実行する**: iPhone を Mac につなぎ、スキーム `FocusAction`・実行先に実機を選んで ▶（`⌘R`）。
   この方法でインストールしたアプリは自動的に Development につながる。
2. **データを保存する**: タグを作り、**タグ付きでセッションを1件完了**させる。これで Development にスキーマが自動で作られる。
3. **Development 側を確認する**: [CloudKit Console](https://icloud.developer.apple.com/) → `iCloud.FocusActionContainer` → 環境を **Development** →
   Schema → Record Types で、`CD_FocusSession` / `CD_Tag` に必要なフィールドがそろっているか確認する。
4. **Production に反映する**: Development を表示したまま「**Deploy Schema Changes...**」→ 差分を確認して Deploy。
5. **反映を確認する**: 環境を **Production** に切り替え、同じフィールドがあるか確認する。
6. **TestFlight 版で試す**: Xcode 版で上書きされているので、TestFlight 版を入れ直し、**新しく作ったデータ**で同期を確認する。

## 注意点

- **Development と Production はデータが別。** Xcode 版で作ったデータは TestFlight 版に出てこない。同期の確認は2台とも同じ環境・同じ Apple ID で行う。
- **Production に反映したスキーマは削除や型の変更ができない**（追加のみ）。Deploy 前に Development のスキーマが最終形か確認する。
  Development が散らかっている場合は、Deploy 前に「Reset Environment」でリセットし、Xcode 版で1回同期し直してから Deploy してもよい（Development のデータは消える）。
- **`@Model` にプロパティを追加したら、毎回この手順（Development で同期 → Deploy）が必要。** 忘れると TestFlight / App Store 版だけ同期が止まる。
- TestFlight 版のログは Xcode では見られない。実機を Mac につなぎ、Console.app で `FocusAction` のプロセスを絞り込み、`CloudKit` で検索する。
- Xcode 実行時は、スキームの Arguments に `-com.apple.CoreData.CloudKitDebug 1` を追加すると詳しいログが出る。

## 検討して見送ったこと

- **コンテナの削除・作り直し**: CloudKit のコンテナは削除できず、Production もリセットできない。
  「作り直し」は別IDのコンテナへの乗り換えになり、既存データ（TestFlight テスターのデータも含む）が見えなくなる。
  今回は足りないフィールドを Deploy すれば直るため、見送った。
  - Production に残っている使わないフィールド（旧 `CD_tags` など）は消せないが、動作には影響しない。

## 別件: ロック画面から戻るとタイマーの残り時間が戻る

### 原因

`TimerViewModel.handleScenePhaseChange` で、`.background` と `.inactive` の両方で `backgroundDate` を上書きしていた。
復帰時は `.background → .inactive → .active` と遷移するため、`.inactive` の時点で `backgroundDate` が「今」に上書きされ、
`.active` で計算される経過時間がほぼ0になる。その結果、ロックした時点の残り時間に戻って見えていた。

関連する問題:
- コントロールセンターなどで `.inactive` になるだけのときはTimerが動き続けるのに、復帰時にさらに経過時間を引くため、残り時間が二重に減る。
- `tick()` で1秒ずつ減らす方式なので、処理の遅れが積み重なると実際の時刻とずれる。

### 対応

残り時間を1秒ずつ減らす方式をやめ、**終了時刻 `endDate` を保持して `endDate − 現在時刻` で毎回計算する方式**に変更した（`TimerViewModel.swift`）。

- 開始・再開時に `endDate = 現在時刻 + timeRemaining` を設定する。一時停止・リセット・モード切替・完了時は `nil` にする。
- `tick()` は `endDate` から残り時間を再計算する。表示の秒の切り替わりが遅れないよう、更新間隔を 0.25 秒にした。
- 残り時間は小数を含むので、`timeString` は切り上げて表示する。
- `backgroundDate` は廃止した。`.active` に戻ったときに `tick()` を1回呼んで表示を更新し、バックグラウンド中に終了していれば完了処理まで行う。
- Watch 側の `applyRemoteState` でも、受信した状態から `endDate` を設定する。

iOS / watchOS ともシミュレータ向けビルドは成功。実機でのロック → 復帰の動作確認はまだ。

## 別件: タイマー実行中もタグを表示する（2026-10-06）

### 変更前

タイマーの円の中は、開始前・一時停止中はタグ（`TagPickerMenu`）、実行中は「集中...」「休憩中...」、完了時は「完了！」を表示していた。

### 対応

実行中にわざわざ「集中...」に切り替える必要はないため、**完了時以外は常にタグを表示する**ようにした。

- `TimerViewModel`: `statusText` と `isIdle` を削除し、`isCompleted`（`!isTimerRunning && timeRemaining <= 0`）を追加。
- `TimerView+iPhone.swift` / `TimerView+iPad.swift`: `isCompleted` のときだけ「完了！」、それ以外は `TagPickerMenu` を表示。
- 実行中もタグを変更できる。タグは `timerCompleted()` → `saveSession` の時点の `selectedTag` で保存されるため、
  途中で変更するとそのセッション全体が新しいタグで記録される（間違えて始めたときに直せるので、変更可のままにした）。
- 完了時の「完了！」は残した。

iOS のシミュレータ向けビルドは成功。

## 未対応: 一時停止→再開で完了通知が届かない

`toggleTimer()` は通知のスケジュールを `sessionStartDate == nil`（セッションの最初の開始）のときだけ行い、
一時停止時は `cancelAllNotifications()` で取り消す。そのため、一時停止→再開すると通知が予約されないまま進む。

以前は `handleScenePhaseChange` の `.active` 復帰時にスケジュールし直していたため、バックグラウンドを挟めば偶然復活していたが、
`endDate` 方式への変更でその処理がなくなり、一時停止を挟んだセッションでは確実に届かなくなった。
再開時にも `scheduleTimerCompletionNotification(for:in:)` を呼べば直る。
