# 2026-11-01〜03 タイマーのアーキテクチャ整理

ブランチ: `refactor/timer-state`（PR #19 で `refacter/build4` にマージ済み）→ `refacter/build4`

## 背景

`TimerViewModel` が、タイマーの計算・セッション保存・通知・Live Activity・Watch 送信・Widget 更新を一手に担っていて、
`#if os(iOS)` の分岐も多く、テストが1件もなかった（`FocusActionTests` は空のテンプレートのみ）。
直近もタイマーの不具合修正が続いていたため、TCA や Clean Architecture のような重い構成は入れずに、
**「軽量な MV ＋ `@Observable` の Store ＋ 副作用の注入」** に寄せることにした。

## 実施内容

### 1. `TimerState` の切り出し（2026-11-01）

- `FocusAction/Models/TimerState.swift`（新規・iOS/watchOS共通）に、開始・一時停止・リセット・モード切替・tick・
  Watch 状態の反映を、副作用のない struct として移した。
- 現在時刻は `now: Date` で受け取るので、テストで時間を自由に進められる。
- 完了時は `tick(now:)` が `TimerCompletion`（モード・開始時刻・時間）を返す。保存とモード切替は呼び出し側が行う。
- `TimerMode.next`（完了後の次のモード）を追加した。
- `FocusActionTests.swift` に `TimerStateTests` を19件追加した。

### 3. 副作用の注入（2026-11-03）

- `FocusAction/Stores/TimerEvent.swift`（新規・iOS/watchOS共通）
  - `TimerEvent`: `.started` / `.paused` / `.reset` / `.modeSwitched` / `.completed(TimerCompletion)` / `.tagChanged` / `.sessionSaved`
  - `TimerEventContext`（state・tag・modelContext）と `TimerEventHandler` プロトコル
- `FocusAction/Services/TimerEventHandlers.swift`（新規・iOS専用）
  - `NotificationTimerEventHandler` / `LiveActivityTimerEventHandler` / `WatchSyncTimerEventHandler` / `WidgetTimerEventHandler`
  - `TimerEventHandlers.live()` で4つをまとめて返す
- `LiveActivityManager.update` / `WidgetDataWriter.updateTimer` / `TimerSyncManager.sendState` は、
  `TimerViewModel` ではなく `TimerState`（とタグ）を受け取るようにした。Service が ViewModel に依存しなくなった。
- Store から `#if os` がなくなった。プラットフォームの違いは「注入するハンドラ」と `isFromWatch` で表す。
- `TimerStoreTests.swift` を10件追加した（イベントの発行順、メモリ上の SwiftData でのセッション保存）。

### 4. `TimerStore` への移行（2026-11-03）

- `ViewModels/TimerViewModel.swift` → `Stores/TimerStore.swift`。`ObservableObject` + `@Published` を `@Observable` に変えた。
- `FocusActionApp`（iOS）と Watch の App が、`@State` で `TimerStore` を1つだけ生成して `.environment` で配る。
  View は `@Environment(TimerStore.self)` で読む。
- `modelContext` は後から代入するのをやめ、init で `PersistenceController.sharedModelContainer.mainContext` を渡す
  （ルートの `.modelContainer` が環境に入れるものと同じ）。
- scenePhase の監視（フォアグラウンド復帰時の再計算）は、App の `.onChange(of: scenePhase)` に移した。
- Watch での受信の登録（`TimerSyncManager.shared.start(with:)`）は、Watch の App のルートの `.task` に移した。
  `WatchTagListView` を「ViewModel を1つに保つためにルートで持たせる」工夫は不要になったので削除した。
- Combine の `Timer.publish` をやめ、`Task` のループ（`Task.sleep(for: .milliseconds(250))`）にした。

## 動作の変更（不具合修正を含む）

- **残り時間0の状態では開始しない**（1）。以前は Watch が「既に終わっている状態」を受信した直後に再生を押すと即完了扱いになり、
  実際には集中していない25分のセッションが履歴に保存されていた。
  - その代わり、この状態で再生を押しても何も起きない。リセットかモード切替が必要。
- **一時停止 → 再開でも完了通知が届く**（3）。`2026-10-04_CloudKit同期不具合調査.md` の「未対応: 一時停止→再開で完了通知が届かない」を解消した。
  `.started` のたびに、その時点の残り時間で通知を予約し直す。
- **フォアグラウンド復帰時の再計算が、どのタブを開いていても行われる**（4）。以前はタイマー画面の View で受けていた。
- **Compact ⇄ Regular の切り替え（iPhone Duo の開閉など）で View が作り直されても、タイマーの状態が消えない**（4）。

## 決定事項と理由

- **ViewModel を作るのはタイマーだけ。** SwiftData の `@Query` は View からしか使えないため、履歴・タグの画面は
  今のまま `@Query` で取得する。無理に MVVM にすると、CloudKit からの自動更新を自分で配線し直すことになる。
- **タイマーは「画面の状態」ではなく「アプリ全体の状態」として扱う。** Watch・Live Activity・Widget と連動するので、
  View が持つ `@StateObject` ではなく App が持つ Store にした。
- **副作用は「イベント → ハンドラの配列」で注入する。** 4つの副作用はどれも「状態が変わったら外に伝える」だけなので、
  メソッドの多いプロトコルを4つ作るより、1つのイベントを全ハンドラに配るほうが単純で、テストでも記録用のハンドラを1つ差し込むだけで済む。
- **Live Activity はタグ変更で更新しない。** 以前と同じ挙動のまま残した（下の「未実施・引き継ぎ」を参照）。

## トラブル対応

- **Swift Testing で `#expect(completion?.duration == 25 * 60)` が失敗する。** 値はどちらも1500と表示されるのに失敗した。
  Optional チェーンの結果と整数リテラルの比較でマクロの型推論がずれるようなので、`TimerCompletion` 同士を比較する書き方にした。
- **テストターゲットだけ `MainActor` がデフォルトではない。** アプリ本体は `SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor` だが、
  `FocusActionTests` は違うので、テストの struct に `@MainActor` を付けている。
- **`ScenePhase.active` がテストで使えない。** `MemberImportVisibility` が有効なため、テストファイルでも `import SwiftUI` が必要。
- **xcodebuild のログを grep しても何も出ない。** 並列テストの出力が途中で混ざって UTF-8 が壊れ、grep がバイナリ扱いしていた。
  `grep -a` を使うか、`xcrun xcresulttool get test-results summary --path <xcresult>` で件数を確認する。
- **Claude Code から PR を作れない。** このMacに GitHub CLI（`gh`）が入っていなかった。`brew install gh && gh auth login` が必要。
  PR #19 はブラウザから作成した。
- **`refacter/build4` がリモートになかった。** PR のマージ先にするため origin にプッシュした（中身は当時の main と同じ）。

### 気づいたが手を付けていないこと

- **Watch で「既に終わっている状態」を受信したあと再生を押しても何も起きない**（1 の副作用）。困るようなら、
  「残り0なら自動でリセットしてから開始する」形に変える。
- **実行中にタグを変えても Live Activity のタグ表示が更新されない。** 以前からの挙動。直すなら `LiveActivityTimerEventHandler` で
  `.tagChanged` のときにも `update` を呼ぶ。
- **`NotificationManager` は `ObservableObject` のまま。** `SettingView` が `@ObservedObject` で購読している。揃えるなら `@Observable` にする。
- **`TimerEventHandler` の各実装（通知・Live Activity など）自体のテストはない。** どのイベントでどの API を呼ぶかの対応は単純なので、
  `TimerStore` が正しいイベントを出すことだけをテストしている。
